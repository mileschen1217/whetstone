# 0011 — Project memory is pages of what holds now, in the repo, integrated when a unit ships

2026-09-20. Accepted.

**Context.** A later epic needs what earlier ones settled and the code does not show. Four ways to keep it were on the table. Decision records added one after another (ADRs): the reader has to replay them to know what holds, a record and the state it describes have to be kept in step, and measured here, two records that disagreed sent the agent back to the owner every time, leaning to the older one. A rule telling the reader which record holds: tried, no Δ. A session-memory tool that captures and retrieves by similarity: nothing in it is signed or checked, retrieval is not a list that can be walked, it lives outside the repo and on one harness, and it needs hooks. Pages that say what holds now, rewritten where they stand: with such a page the agent needed no instruction to read it correctly.

**Decision.** `.whetstone/memory/` in the repo: one page a topic, frontmatter `about:` and `scope:`, statements of what holds now, each with a check or `check: none` and a source. The source points one way, at a `D-n` of an accepted `epic.md`, which is never edited afterwards; a page never points at another page, and the workflow writes no ADRs. Only `ship` writes, rewrites or lists for removal, in the working tree of the unit that makes the statement true, each change a row the owner sees. A page holds no history. What can be read from the code is not stored. There is no cap on the pages; what is bounded is what one invocation loads (the frontmatter scan, then the pages in scope), and a page that grows is split. A search index, if one is ever needed, is generated from the pages and can be thrown away.

**Overturned by.** A real project where `intent` misses a page that exists (the owner is asked twice, or learns of a decision after a merge: events in `evals/RETRO.md`) and the scan cannot be split further; or pages that owners stop reading on the ship page, so that statements enter unsigned.
