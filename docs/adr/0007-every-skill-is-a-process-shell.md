# 0007 — Every skill is a process shell, not knowledge of the craft

2026-09-20. Accepted. Supersedes 0001, which said this of `review` only.

**Context.** Stage by stage the bare reference model already did the craft: it found planted defects in diffs, built to held-out tests, listed every exception on a ship page, wrote thick checks and listed its own decisions in a brief, and asked the owner the right behaviour questions. Sentences that taught the craft were tried in each stage and showed no Δ: what to look for in a review, test-first and a refactoring pass in a build, two texts aimed at the number of criteria in a brief. What the bare model did not supply was structural each time, and each skill now holds only that (`evals/BASELINE.md`, one section a stage).

**Decision.** A skill holds what the model will not supply by itself: who may do a step (a reviewer who did not write the change, a check author who is not the builder, an owner who signs), where a step ends (a list walked, one round, a fixed set of parts), the file the next stage reads, and the one question per stage that bare runs leave unasked. It does not say how to review, build, specify or interview.

**Overturned by.** A case from real history where a sentence of craft knowledge raises the outcome measure on the reference model without raising volume, at 6 runs or more; or a new reference model that is red, bare, on a stage's cases.
